# 版本路线图

早期需求和架构文档使用“v0.1.0 MVP”指代第二阶段的完整交付范围。项目实际采用增量发布后，版本边界调整如下；功能需求本身不变。

| 版本 | 状态 | 交付范围 |
|---|---|---|
| `v0.1.0` | 已发布 | Go/Gin项目骨架、双HTTP Server、SQLite/GORM数据层、幂等日志接收、可观测性基础 |
| `v0.2.0` | 开发中 | 日志列表、详情、级别统计、服务统计及查询测试 |
| `v0.3.0` | 计划中 | `log-producer`、Filebeat、Logstash、Dockerfile、Compose和持久化挂载 |
| `v1.0.0` | 计划中 | 完整端到端验收、性能与恢复验证、稳定文档和正式交付 |

## 发布原则

- `main`只保存已经发布或准备发布的稳定版本。
- 日常功能从`develop`创建`feature/*`分支，通过PR合并回`develop`。
- 一个里程碑完成后从`develop`创建`release/*`分支，完成最终验证后同时回合`main`和`develop`并打标签。
- `v1.0.0`表示原始MVP需求全部达到Definition of Done，不等同于第一次可运行版本。

## 当前开发顺序

```text
v0.1.0 接收核心
→ v0.2.0 查询与统计
→ v0.3.0 自动采集与Compose
→ v1.0.0 完整验收
```
